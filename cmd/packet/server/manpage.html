Software Manual

The SCCo Packet Messenger software supports Amateur Radio Emergency Service (ARES®) packet radio messaging in Santa Clara County, California. It is the successor to PacFORMS (by Phil Henderson KF6ZFQ), PackItForms (by John Kristian W6JMK), and packet shell (by Steve Roth KC6RSC). The Packet Messenger software operates in two modes: as an Outpost add-on, and as standalone packet messaging software.

Most Santa Clara County ARES/RACES packet operations and operators use the Outpost Packet Message Manager software, which is the county standard packet message manager. In these environments, the SCCo Packet Messenger acts as an add-on to Outpost, adding the ability to send and retrieve messages containing standard county forms.

The SCCo Packet Messenger can also be used as a packet message manager in its own right, independent of Outpost. It provides both a graphical user interface and a scriptable command line interface. It supports both manual operation (operator interacts with TNC) and automatic operation (software handles the TNC). It runs on any operating system and has no external dependencies other than a browser for the graphical user interface.

Outpost Add-On Operation

The SCCo Packet Messenger software is bundled in the county standard packet software installer. When installed using that installer, it is automatically connected to Outpost. If the SCCo Packet Messenger software is installed separately for some reason, it can be connected to Outpost by running the packet install command. The connection can be broken with the packet uninstall command, or by uninstalling the SCCo Packet Messenger software.

Whenever an Outpost user asks to view a forms message (i.e., one that starts with !SCCoPIFO! or similar), Outpost will relay the request to the SCCo Packet Messenger, which will render the original form in PDF format and open it in a browser window.

Similarly, whenever an Outpost user asks to create a new forms message using one of the entries in the "Forms" menu, Outpost will relay the request to the SCCo Packet Messenger, which will open the appropriate form in a browser window. When the user submits that form, the SCCo Packet Messenger will encode it for transmission and hand it back to Outpost. It will also render the message in PDF format so that it can be printed if desired.

The first time that the SCCo Packet Messenger is used each day, it will contact the SCCo ARES/RACES web server and look for updated versions of the Santa Clara County standard forms. These will be installed automatically. (Obviously this only works if the system has Internet access.)

The SCCo Packet Messenger software handles all county standard forms. Individual systems may have other Outpost add-ons that handle other forms, such as city-specific forms. These are independent and not affected by the SCCo Packet Messenger.

Standalone Packet Messenger Operation

The SCCo Packet Messenger can be used without Outpost, in both graphical and command line interfaces. When run standalone, it operates on an "incident", which is a folder containing a set of related messages that get reported on the same ICS-309 message log form. A new "incident" should be created in a new folder whenever you would normally start a new ICS-309.

To start the SCCo Packet Messenger's graphical interface, run the packet gui command (or, if installed on Windows through the SCCo standard packet installer, C:\PackItForms\pifo.exe). If you are in an incident folder when you run that command, or you add a folder path on the command line, it will start in that incident. Otherwise, it will ask you to choose or create an incident folder. To use the SCCo Packet Messenger's command line interface, you should be in the desired incident folder before invoking the packet command.

Incident Settings

Each incident has its own settings that control how its messages are handled. Only a few of the settings are required:

  • Your call sign and name. You can also supply a tactical call sign and station name if appropriate.
  • The starting message ID to be assigned to new messages. You can assign separate message ID sequences for incoming and outgoing messages, but usually they share the same sequence.
  • The BBS you're connecting to and the method of connecting to it. Three connection methods are currently supported:
    • Manual operations. The SCCo Packet Messenger doesn't connect to the BBS for you; it just gives you commands you can paste into a separate connection that you manage. For this method, you need to provide the BBS name (so the software can use it in message headers) but nothing else.
    • Serial+TNC connection. The SCCo Packet Messenger will connect to the BBS (that you specify by AX.25 address) by talking to a TNC (of a type you specify) through a serial port (that you specify).
    • Telnet connection. The SCCo Packet Messenger will connect to the BBS (that you specify by name, hostname or IP address, and port number), logging in with your tactical or FCC call sign and the password you specify. (Note: SCCo ARES/RACES issues passwords for telnet access only to network maintenance staff and others with demonstrated need.)

The rest of the incident settings are optional. These include:

  • ICS-309 header information: incident name, activation number, and operational period. These are shown on the generated ICS-309 forms.
  • Bulletin retrieval settings: you can specify which BBS areas to retrieve bulletins (and SCCo notices) from, and how often to check for them.
  • Defaults for new messages: you can specify default values for the To Address, To ICS Position, To Location, From ICS Position, and From Location fields of messages. You can also specify default body text (e.g., **** This is drill traffic ****) to be put in the primary text field of new messages.

When creating a new incident, you are prompted to supply these incident settings (at minimum the required ones). To change them later, use the Incident → Incident Settings menu item (graphical interface) or the edit config command (command line interface).
