This is the message ID to assign to the first message you receive. It should have the form XXX-###P, where XXX is a three-letter prefix identifying your station, ### is a sequence number, and P is an optional suffix letter (usually "P" for packet). Subsequent received messages will use the same prefix and suffix and successively higher sequence numbers.
This is the message ID to assign to the first message you send. It should have the form XXX-###P, where XXX is a three-letter prefix identifying your station, ### is a sequence number, and P is an optional suffix letter (usually "P" for packet). Subsequent sent messages will use the same prefix and suffix and successively higher sequence numbers. This is usually the same as the Starting Message ID for Receive, in which case sending and receiving message IDs will be interleaved.
BBS Communications
This selects how the packet software will connect to the BBS. "Manual" means the packet software makes no BBS connections; you handle them manually (usually through a terminal emulator talking to a TNC). "Serial+TNC" means the packet software will talk to a TNC through a serial port, and use it to connect to the BBS over the air. "Telnet" means the packet software will connect to the BBS over the Internet using the Telnet protocol.
If checked, the packet software will generate a delivery receipt for every incoming message, and leave it in "ready" state for you to send manually at your convenience. If not checked, the packet software will not generate delivery receipts except when asked. This setting applies only to manual BBS communications. Delivery receipts are always generated and sent automatically in non-manual BBS communications.
This setting specifies which type of TNC is in use, so that the packet software knows what command set to use.
This identifies the serial port that the TNC is connected to. On Windows, this will be "COM#", where # is some number (most commonly 3). On Mac OS and Linux, this will be /dev/ttyXXX, identifying a character device file for the port. The packet software expects that the TNC is using 9600 baud, 8 data bits, no parity bit, 1 stop bit, and RTS/CTS flow control. (These are the default settings for most TNCs.)
This is the AX.25 address of the BBS to connect to. It will be the BBS call sign followed by a dash and a number from 0 to 15 (usually 1).
This is the call sign of the BBS to connect to.
This is the hostname or IP address of the BBS.
This is the TCP port number to connect to on the BBS. It is a number between 1 and 65534.
If checked, the packet software will connect to the BBS using the password it has saved for the Tactical Call Sign or Operator Call Sign listed above. To use a different password, uncheck this box and enter the new password. This is the password to use when connecting to the BBS for the Tactical Call Sign or Operator Call Sign listed above.
Bulletin Retrieval
This is the name of the notice or bulletin area to check. It is either an SCCo notice area (XSCPERM, XSCEVENT, XSCTEST) or a BBS bulletin area (topic@distribution). The most common BBS bulletin areas used by us are xxx@XSC, where xxx is a three-letter city prefix. This identifies how frequently the packet software should check for new notices or bulletins in this area. To check during every BBS connection, set this to 1 minute. To stop checking, set this to zero, or remove the area name. If this box is checked, the area will be checked for new notices or bulletins on the next BBS connection, and will then resume the defined schedule after that.
